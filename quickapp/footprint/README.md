# 足迹｜openvela 足球比赛智能采集器

## 一、作品简介

“足迹”是一款运行在 openvela 圆形智能手表上的足球比赛智能采集器。它让球员无需依赖手机即可在手表端完成球场选择、赛前检查、进攻方向确认、比赛记录、暂停/继续、上下半场切换、异常恢复和本地保存；手机连接与同步是增强能力，而不是开始记录的前置条件。

作品重点解决业余足球比赛中“过程数据难以持续记录、网络或定位短暂异常就容易中断、赛后数据缺少可靠留存”的问题。比赛数据优先保存在手表本地，恢复连接后再同步；未完成比赛在再次打开应用时可继续记录或安全保存。

## 二、选题方向

**手表应用创新。**

“足迹”围绕圆形智能表盘的可视区域与运动中的快速操作重新组织比赛流程：用短路径完成开赛，用大按钮降低误触风险，用本地优先存储保证离线可用，并将赛前检查、实时记录、控制页和比赛记录形成闭环。

## 三、核心功能

- **本地快速开赛**：选择 5 人制、7 人制、8 人制、11 人制或自定义训练，不依赖手机也可开始演示和记录。
- **赛前检查**：展示 GNSS、心率、电量、存储空间、当前球场与进攻方向。
- **实时比赛记录**：记录时长、距离、心率和配速，支持暂停、继续与状态面板下拉查看。
- **上下半场管理**：结束上半场后进入中场休息，下半场自动反转进攻方向。
- **可靠性设计**：GNSS 暂时失效时持续计时和记录心率；应用异常退出后可恢复未完成比赛；结束比赛采用二次确认。
- **本地保存与记录查询**：完成后优先保存至手表本地，比赛记录支持查看详情和左滑删除。

## 四、目录结构

```text
足迹/
├─ src/                         # Vela 快应用源码
│  ├─ manifest.json              # 应用清单、权限、466 × 466 设计宽度
│  ├─ common/                    # 比赛状态机、记录与模拟数据逻辑
│  └─ pages/                     # 恢复、选场、赛前检查、记录、控制、历史等页面
├─ test/                         # Node.js 逻辑与页面回归测试
├─ skills/
│  └─ vela-sim-autostart/        # 可复用的 Vela 模拟器自动部署 Skill
├─ submission/                   # 本地提交暂存：报告候选、RPK、视频与日志说明
├─ auto-start.cjs                # 构建、部署、启动 redmi_watch 模拟器脚本
├─ package.json                  # 构建与测试脚本
└─ README.md                     # 本作品说明
```

正式比赛仓由 `repo init` / `repo sync` 创建后，组委会采集器会在其根目录下自动生成 `logs/<GitHub账号>/...jsonl`。本地当前目录尚未处于带 `.repo/` 的官方工作区，因此没有有效 AI Coding 日志；不得手动伪造日志。

## 五、运行方式

### 1. 准备环境

- Node.js 16 或更高版本
- Vela / AIoT 工具链与 redmi_watch 模拟器
- 本项目的 npm 依赖

```powershell
Set-Location 'E:\Openvela大赛\足迹'
npm install
```

### 2. 执行测试

```powershell
npm test
```

测试覆盖比赛状态机、恢复流程、赛前检查、历史记录删除、圆屏布局、状态面板和记录控制等逻辑。

### 3. 构建 RPK

```powershell
npm run build
```

构建成功后会在 `dist/` 生成 `.rpk`。本地本次验证构建的提交暂存包位于：

[`submission/release/足迹_debug_0.2.0.rpk`](submission/release/足迹_debug_0.2.0.rpk)

### 4. 启动模拟器演示

```powershell
node auto-start.cjs
```

该脚本会构建应用、附着或拉起 `redmi_watch` 模拟器、安装 RPK 并启动应用。详细的可复用操作说明见 [`skills/vela-sim-autostart/SKILL.md`](skills/vela-sim-autostart/SKILL.md)。

## 六、数据与验证边界

应用已声明并使用 Vela 的定位、健康、存储、电量、网络等系统能力。模拟器中的 GNSS、心率、电量、手机连接和同步状态使用确定性 Demo/Test 数据，目的是保证演示可重复；真机传感器读数、手机同步与签名配对仍需在目标设备和配套环境中完成验证。演示与答辩材料会明确区分模拟数据与真机能力。

## 七、AI Coding 使用说明

本项目在需求拆解、比赛状态流转设计、圆屏布局适配、Vela 页面编码、构建问题定位、测试补充和提交文档整理中使用 AI Coding 协作。

AI 的具体帮助包括：

- 将比赛记录拆分为赛前检查、记录、控制、中场、结束确认、保存、历史与恢复等可验证状态；
- 根据 466 × 466 圆屏约束调整页面布局与操作路径；
- 辅助定位 Vela 构建、模拟器启动和 RPK 安装中的工具链问题；
- 辅助补充 Node.js 回归测试、提交清单和可复用的模拟器自动部署 Skill。

有效 AI Coding 原始日志必须按组委会指南，在官方 `.repo` 工作区安装采集器后自动写入比赛仓 `logs/` 目录，再与代码一起提交。当前项目仍缺少该官方日志采集环境；日志完善状态见 [`submission/SUBMISSION_CHECKLIST.md`](submission/SUBMISSION_CHECKLIST.md)。
